# 研究完了・論文投稿ロードマップ

## 完了の定義

研究完了とは、単に実装が動くことではなく、次の状態を指します。

- 主張が明確で、各主張を支える再現可能な実験がある
- ベースラインとの比較条件が公平である
- 失敗例、制約、適用範囲を説明できる
- 論文中の全ての数値と図表について生成元を追跡できる
- 第三者が記載された手順から主要結果を再現できる
- 投稿先の形式、ページ数、匿名化、締切を満たしている

## 1. 問いと完了条件を固定する

- [ ] 研究課題を 1 文で書く
- [ ] 検証可能な仮説を定義する
- [ ] 新規性を既存研究との差分として書く
- [ ] 論文の貢献を最大 3 点に絞る
- [ ] 「何が確認できたら研究を終えるか」を数値または成果物で決める
- [ ] 対象外にする論点を決める

成果物: `docs/research-question.md`

## 2. 関連研究と位置づけを固める

- [ ] Stress minimization の代表的手法を整理する
- [ ] SGD ベースのグラフレイアウト研究を整理する
- [ ] GPU 並列化手法と競合回避手法を整理する
- [ ] 各論文について「本研究との違い」を 1〜2 文で記録する
- [ ] 引用情報を BibTeX に集約する

成果物: `references/references.bib`、`manuscript/outline.md` の関連研究節

## 3. 実験計画を凍結する

- [ ] 比較対象の実装とバージョンを決める
- [ ] データセットと選定理由を決める
- [ ] Stress、実行時間、メモリなどの評価指標を定義する
- [ ] ウォームアップ、反復回数、seed、停止条件を決める
- [ ] CPU/GPU、OS、コンパイラ、依存関係を記録する
- [ ] 失敗時・OOM 時・タイムアウト時の扱いを決める
- [ ] 事前に必要な図表と、それが支える主張を対応づける

成果物: `docs/experiment-plan.md`

## 4. 実装と測定系を確定する

- [ ] ベースラインと提案法の入力・停止条件を揃える
- [ ] release build で測定する
- [ ] ログへ commit hash、seed、条件、所要時間を出す
- [ ] Stress の計算が実装間で一致することを小規模グラフで確認する
- [ ] 計測自体のオーバーヘッドを確認する
- [ ] 主要ケースの再実行で結果が安定することを確認する

成果物: 再現可能な実験コマンド、検証記録

## 5. 最終実験を実施する

- [ ] 小・中・大規模データセットで実行する
- [ ] 各条件を決めた回数だけ反復する
- [ ] 生ログを変更せず保存する
- [ ] 各実験を `docs/experiment-log.md` に登録する
- [ ] 異常値を恣意的に除外せず、扱いと理由を記録する
- [ ] 再実験が必要な条件を洗い出し、完了させる

成果物: 実験ログ、集計前データ、実験台帳

## 6. 分析して図表を確定する

- [ ] 中央値・分散など、計画した統計量で集計する
- [ ] 高速化率と解品質のトレードオフを確認する
- [ ] グラフ規模に対するスケーリングを確認する
- [ ] メモリ使用量または最大処理可能規模を確認する
- [ ] 仮説に反する結果と失敗例を分析する
- [ ] 各図表に元データと生成手順を添える

成果物: `figures/`、`tables/`

## 7. 論文を書く

- [ ] 結果と図表を先に書く
- [ ] 手法を再実装できる粒度で書く
- [ ] 導入で課題、ギャップ、着想、貢献をつなぐ
- [ ] 関連研究で差分を明確にする
- [ ] 制約と妥当性への脅威を書く
- [ ] 要旨と結論を最後に整合させる
- [ ] 全ての主張に根拠または引用があることを確認する

成果物: `manuscript/outline.md` から発展させた原稿

## 8. 再現性と投稿前レビュー

- [ ] クリーン環境で主要実験を再現する
- [ ] 論文中の数値を元データと照合する
- [ ] 図の軸、単位、凡例、色覚アクセシビリティを確認する
- [ ] 引用漏れ、参照切れ、未定義の略語を確認する
- [ ] 共著者または第三者レビューを反映する
- [ ] 投稿規定、匿名化、ページ数、補足資料を確認する
- [ ] 提出版と対応する commit/tag を固定する

成果物: 投稿 PDF、再現手順、リリースタグ
