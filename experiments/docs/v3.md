# v3：esa #9029の実験1〜7

100件（原データの小中規模20・大規模80）を計画に保持する。データ取得・同一性・前処理に問題がある入力は、理由を記録して欠測として扱う。正規配布93件を非零パターンへ変換し、自己ループ・重複・方向・重みを除去して最大連結成分を抽出する。元頂点番号の対応・source/input checksum・次数統計を保存する。

実験1・4は基本比較の再集計。基本比較は5 seed、収束比較は代表18グラフで10 seed。タイル幅は代表6グラフで1..1024の2冪、W=1024、T=1のみinner shuffle無効。pivot数は代表6グラフで50/100/200/400。T=1024とpivot200は基本比較の同条件を再利用する。

6手法のrelease binaryは共通target `target/v3-release/release/` にビルドする。例：`cargo build --release --locked --manifest-path implementations/full/vram-lock-native/Cargo.toml --target-dir target/v3-release`。

通常比較では座標snapshotを取らず、各反復の時間だけ記録する。反復時間の代表指標はtraceにあるalgorithm intervalの合計で、追加JSONL書込を除外する。既存recordの時間はreported_iteration_time_msに残す。詳細収束では0/1/2/3/5/8/10/15反復の実座標を保存し、品質は後処理で評価する。15反復の学習率を保ち、短い反復数での別実行から曲線を作らない。

全手法で8,000頂点以下はexact、超過は256始点のsampled stress。始点用seedは固定・pivot用乱数から独立。代表例で64/256/1024始点による差を補足評価する。CPUはf64、GPUはf32。

時間制限・RSS制限・ディスク余裕を親プロセスで監視し、超過は失敗結果として保存する。最大RSSはmacOS `/usr/bin/time -l` の値と監視値を記録（共有GPUメモリの厳密な最大量とは異なる）。初回の入力やMetal初期化も含む壁時計時間と、SGD反復時間を区別する。再開時は既存runを保護し、binary・runner・全計画・データ一覧のhashと上限が変わっていれば拒否する。

`config/plan.json`が全計画、`raw/results.jsonl`が全成否、`raw/artifacts/`が各runの出力、`warmups/`が事前試運転。`config/execution.json`とsource snapshotで実測版を保存する。グラフ・同seed・系列・pivot等が一致するCPUとGPUのみ対応比を計算する。欠測を速度比0や1に置換しない。

事前試運転が時間・メモリ等で失敗した設定は、同じ設定の正式5 seedを実行せずwarmup_failedとして保留する。試運転の実ログと原因を保存し、未実行件数と実際の失敗実行数を区別する。失敗の繰り返しで端末を過負荷にしないための、本計測前に固定する運用規則である。
