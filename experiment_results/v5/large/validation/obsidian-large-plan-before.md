# 超大規模グラフ実験

[[0_概要]] / [[11_共通条件と出典]] / [[12_実験設計の点検]]

## 目的

RR Sparse（GPU）が大規模入力をどのpivot数で処理できるか、その時間・メモリ・最終品質を調べる。CPU・Atomicは実行せず、CPUとの速度比や不可能性は検証しない。

## 実験条件

| 項目 | 条件 |
|---|---|
| 方式 | RR Sparseのみ |
| pivot数と順序 | 1000 → 500 → 200 → 100 → 50 |
| seed | 0,1,2,3,4 |
| 各seedの実行回数 | 各pivot設定で1回 |
| 1実行のSGD反復数 | 15 |
| epsilon | 0.1 |
| GPU条件 | 相の分割なし、頂点別pivot順序を維持 |
| 取得データ | 完了可否、SGD時間、総計算時間、peak RSS、最終推定Full Stress |
| 品質評価 | 固定64始点、評価seed=0、最終座標のみ |
| 本測定数 | 14×5×5＝最大350実行 |
| レイアウト制限案 | 時間による打切りなし。RSS 18 GiBは容量条件案（24 GiB機の場合） |
| 品質評価の制限案 | 時間による打切りなし |
| ウォームアップ | [[11_共通条件と出典]]。本測定数には含めない |

## 実行手順

1. 不要なプロジェクト・関連プロセスを終了し、利用可能メモリとメモリプレッシャーを記録する。
2. 各グラフでp=1000から順に確認する。必要メモリが上限を明らかに超える設定は確保前に未実行理由を記録し、次のpへ進む。
3. 実行可能な各pで5 seedを測る。最初に成功したpだけで止めない。前の実行のCPU/GPUメモリを解放してから次へ進む。
4. 最終座標取得で計時を止め、同じ座標のStressを後から評価する。描画は別処理にする。
5. 特定seedの失敗から他seedの失敗を推定しない。実行前に確定する資源不足だけは設定全体を省略できる。

## 測定と集計

| 項目 | 規則 |
|---|---|
| 集計 | 各pの5 seedの中央値・最小〜最大、成功数/5。失敗があれば成功例のみの集計と明記 |
| p間の比較 | 同seedの初期座標・同じStress始点を共用。pivot列は可能なら共通の先頭部分を使い、その対応を記録 |
| 品質評価 | 64始点の推定値。各始点の寄与を保存し、小差の断定を避ける |
| メモリ | peak RSSに加えGPU割当上限、メモリプレッシャー・swapを記録 |
| 未実行 | 見積もり超過と実測のOOM・timeoutを区別 |

各seed1回のため通常比較と同じ水準の実行時間の再現性評価にはならない。pを大きい順に測るため順序効果も残る。各設定前に機材状態を揃え、主目的を適用可否・容量評価に置く。

## 実施前の確認

- p間の初期配置一致、メモリ見積もり、出力seedを検証する。
- CPU/GPU双方の常駐配列・一時バッファ・コピーを見積もる。RSS単独でGPUメモリの厳密な上限とはしない。
- Europeの距離配列1本だけでp=1000は約189.66 GiB、p=50は約9.48 GiB（4np bytes）。これらは総使用量ではなく下限の一部で、p=50も成功保証はない。
- SNS系のスケールフリー性と取得後のn,mは未確定。入力を確認する。
- 異なる国やSNSは構造も異なり、純粋なサイズだけの拡大実験ではない。
