# 共通条件と出典

[[0_概要]] / [[10_グラフ選定]] / [[9_計測時間]]

通常実験と追加の超大規模実験は実施済み。以下は採用条件と計画時の確認項目。結果・論文用チャートと取得できなかった計時区間は[[5_実験結果まとめと論文用チャート]]を参照。実施状況と計画との差は[[12_実験設計の点検]]および各考察に記載する。

## seed・実行回数・反復数

- seed：初期配置、Sparseのpivot、更新順等の乱数条件を識別する番号。乱数ストリームの対応と生成方法を実装版とともに記録する。
- 各seedの実行回数：同じ入力・乱数条件で最初から実行し直す回数。repetitionをseedに足さない。
- SGD反復数：1実行内で更新集合を処理する周回数。全実験15反復、epsilon=0.1。
- 同一seedの繰り返しを独立した初期配置として数えない。
- 方式間で初期座標と頂点ID対応を確認する。精度変換がある場合は共通の元座標と変換方法を保存する。Sparse内ではpivot・距離・重みのfingerprintも一致させる。
- FullとSparseの目的関数は異なるため、両者の学習率配列の一致は強制しない。

## 入力と実行条件

- [[10_グラフ選定]]の公開固定入力を使う。無向・無重み・自己ループと重複を除去した最大連結成分へ統一する。
- 入力の取得URL、元ファイルと正規化後ファイルのSHA-256、処理後n,m、頂点ID対応を保存する。
- RR Full：共通T=1024（タイル結果確認後のユーザー指定）、W=1024、shared、外側・内側shuffleあり、分割なし（phase_chunks=1）に固定する。
- Sparse：通常p=min(200,n)、超大規模p=1000,500,200,100,50（この順で試す）。RR Sparseは相の分割なし（phase_chunks=1）。pivot選択方式も記録する。
- 同一機材・電源条件・実装commit・ビルド設定を固定する。機材案はApple M4 Pro、統合メモリ24 GiB。OS・GPU・ドライバ／backend・CPUスレッド数・各方式の数値精度は測定時に記録する。
- 実験は同時実行しない。同一seed・repetition内の方式順を実行順seed=20261107で並べ替え、実行順一覧を保存する。
- グラフ×方式×設定ごとにseed=999で1回ウォームアップし、集計から除外する。タイル選定では方式だけでなくTの順序も並べ替える。超大規模のpは指定どおり降順とする。以後の測定は毎回初期状態から開始する。セッション再開時は再度ウォームアップする。

## Sparseの更新順と実装確認

RR Sparseは片側相と両側相を分割せずに実行する（phase_chunks=1）。頂点ごとのpivot順序は維持し、分割数だけを変更する。分割による追加のGPU投入を避ける方針であり、未測定の速度改善率は記載しない。

2026-11-06にRR Full・RR Sparseの標準実装を分割なしへ変更。Sparseは頂点ごとのpivot順序を維持する。実験前に再ビルドし、出力のrr_phase_chunks=1とSparseのrr_pivot_orderを確認して実装版を固定する。旧v4・full16専用ランナーは過去の分割条件を前提とするため、新しい計画では使用しない。

## 実験前のメモリ確保

実験機の不要なメモリ使用を減らし、同時に保持する実験データを最小限にする。実験条件（グラフ、pivot数、seed数、反復数、評価始点数）は省メモリのために無断で減らさない。

| 段階 | 運用 |
|---|---|
| 実験前 | 作業を保存し、不要なプロジェクト・エディタ、ブラウザタブ、開発サーバー、ビルド監視、コンテナを終了する。ウィンドウを閉じた後も関連プロセスが残っていないか確認 |
| ビルド | 必要なreleaseバイナリを測定前に準備し、測定中はビルド・テスト・別の実験を動かさない |
| 実行 | グラフ・方式・seed・repetitionを並列化せず、常に1実行ずつ。各実行を独立した子プロセスとして起動 |
| 入力 | 今回使うグラフだけを読み込む。次のグラフの先読み・全グラフのキャッシュを行わない |
| 計測と評価 | 15反復のレイアウト終了・計時終了後に、同じ最終座標のStressを逐次評価。途中配置の保存や別レイアウトの同時実行を行わない |
| Stressのメモリ | 全評価始点の距離表を一括保持せず、1始点ずつ処理して集計する。評価始点数は通常256・超大規模64を維持 |
| 描画・図表 | 測定時は起動しない。必要な座標を保存し、測定の終了後に1件ずつ描画・集計する |
| 実行終了 | 子プロセスの終了を待つ。CPU/GPUの使用量が落ち着いたことを確認してから次を起動する |
| 大規模 | p=1000→500→200→100→50の順を維持。明らかな容量超過は確保前に記録して次の設定へ進み、実行中にpを変更しない |

実験開始時と各実行の前後に、利用可能メモリ・メモリプレッシャー・swap使用量を記録する。実行中はpeak RSS、取得可能ならGPU割当も記録する。swap使用量の増加や高いメモリプレッシャーが続くときは次の実行を開始せず、不要な処理を確認する。時間だけを理由に実行中のレイアウトを打ち切らない。

OSに必要な処理と実験管理プロセスは維持する。ファイルキャッシュを強制消去する操作は行わず、同じ環境条件で測定する。

現行の共通ランナーは各方式を子プロセスで逐次実行する。共通Stress評価器も1始点ずつBFS距離を計算する。実行中の不要なGPUバッファ・前処理データがすべて早期解放されることまでは確認していないため、内部メモリ削減済みとは扱わない。

## 時間と集計

主指標はSGD経過時間（⑤）と総計算時間（⑩）。GPU計算pass合計（⑨）は補助指標。定義は[[9_計測時間]]に従う。SGD経過時間/15とGPU計算pass合計/15を混同しない。

速度と最終Stressは同じレイアウト実行から得る。途中座標保存は行わず、最終Stress評価と描画は速度の計測終了後に行う。総計算時間は入力読込開始からCPU上の最終座標完成までを直接測る。GPU timestampが取得できなければGPU計算pass時間は未計測にする。

速度・最終Stress・タイル選定は同一seedの3回を中央値にまとめ、その後seed間の中央値・最小〜最大を報告する。超大規模は各pでseed 0〜4を各1回とし、5 seedの中央値・最小〜最大と成功数を報告する。CPUとの比はグラフ・seed・repetitionを対応させたrunごとの比を求め、その後にseed内・seed間の順で集計する。方式ごとの中央値を先に割る方法と混同しない。成功seed数と予定seed数も表示する。

## 停止条件案

| 対象 | レイアウト1実行の上限 | RSS上限 | 別処理のStress評価上限 |
|---|---:|---:|---:|
| タイル・速度・Stress | 時間打切りなし | 8 GiB（案） | 時間打切りなし |
| 超大規模 | 時間打切りなし | 18 GiB（案） | 時間打切りなし |

RSSは約200ms間隔で観測し、GPUの割当上限・実測メモリも取得可能なら別記する。RSSは専用GPUメモリの厳密な上限ではない。大規模の上限案は24 GiB機を前提とする。

timeout、メモリ超過、実装エラー、未実行、品質評価失敗を分ける。評価だけ失敗してもレイアウト完了記録は保持する。確定的な資源不足で後続を省略するときは理由を残す。失敗を0秒やStress=0として埋めず、速度比は対応する成功データのみで計算する。

## 保存項目

実験ID、グラフ、方式、入力ハッシュ、実装版、全パラメータ、各seed、repetition、実行順、初期座標とpivot等のfingerprint、計測内訳、peak RSS、成功／失敗理由、評価方式・始点リスト、最終座標を保存する。途中のcheckpoint座標・収束時間は取得しない。速度と最終Stressは同じrun_idで結び付ける。

データの出典は[[10_グラフ選定]]を正とする。チャートは各実験ノートの形式に従い、実施後の新しい記録から生成する。

## 本実験開始前の必須確認

[[12_実験設計の点検]]を解消してから測る。ノート上の条件を、実装がすでに満たしているとは扱わない。

| 項目 | 必須条件 |
|---|---|
| 初期配置 | グラフ・seedから独立した乱数ストリームで共通座標を生成し、Full/Sparse・方式間・p間で一致を確認 |
| 乱数の分離 | 初期配置用、pivot選択用、更新順用を区別。repetitionでは乱数条件を変えない |
| 評価seed | 通常0・256始点、大規模0・64始点。評価seedは実装の既定値0を使用する。通常比較ではSGD_STRESS_SAMPLES=256を指定 |
| 計時終了 | 最終座標取得直後、Stress・保存・描画の前。process全体の時間と区別 |
| 時間制限 | manifestのtimeout_secondsをnullにし、レイアウト・Stress評価とも完了まで待つ。計測区間だけは分ける |
| 完了状態 | layout_statusとstress_statusを分け、Stress失敗で速度記録を失わない |
| 実装固定 | commit、dirty差分、binary SHA、Atomicのpair順・retry等の設定を保存し、測定中に変更しない |
| 失敗時の集計 | 主集計は対応する3回すべてが揃うseed。未完了数・成功数・参考値を併記 |
| 温度・キャッシュ | ウォームアップ後の測定であることを明記。冷起動の性能と呼ばず、機材状態・実行順を保存 |

時間による打切りは行わない。メモリ上限は計画案。小規模の機能確認で条件を実施可能と確認してから本測定前に固定する。途中で上限を変えた測定は別の設定IDとして扱う。

## v5補助計測の変更（2026-11-06）

p2p-Gnutella08・T=1のウォームアップで、MetalのGPU counter sample bufferを確保できず停止した。v5では全GPU方式で `SGD_GPU_TIMESTAMPS=0` を指定し、GPU pass時間の補助計測を無効にする。主指標のSGD実経過時間・総計算時間・最終Stressは取得する。アルゴリズム・15反復・seed・タイル・shuffle条件は維持する。

変更前の成功547実行はリポジトリ `experiment_results/v5/validation/pre-counter-disable/` に保存し、本測定には混ぜない。計測条件を揃え、本測定を最初から実行し直す。実装差分・バイナリハッシュ・環境変数をv5へ保存する。

## 通常比較の共通T確定（2026-11-06）

タイル実験結果を確認したユーザーの指定により、通常比較のRR Fullを **T=1024、W=1024、shared、両shuffle有効、phase_chunks=1** に固定する。速度と最終Stressは同じ4,230実行から取得する。

## v5の容量不足と再開（2026-11-06）

通常比較4,175実行成功後、空きディスクが4 GiBを下回ったため、次の実行前で安全停止した。確認時の空きは約0.13 GiB。未起動のVS Codeの再生成可能なC++解析キャッシュを削除して約6.4 GiBを解放し、約6.5 GiBの空きを確認して同じ条件から再開した。入力・実験結果は削除していない。詳細は `experiment_results/v5/logs/disk-recovery-20261106.json`。

CPU・Atomic Sparseの共有前処理はpivot距離表とBTreeMapの制約集合を保持する。p=min(200,n)のとき、最低でも8np + 56(np−p(p+1)/2) bytesが必要になる。これは実装の型と保持集合から求めた下限であり実測peakではない。この下限が物理RAMを超える場合は、割当前に理由を記録して停止するチェックを追加した。数値計算・seed・pivot・反復数・実験バイナリは変更していない。

## 通常比較から大規模実験への移管（2026-11-06）

ユーザーの指示でAS365・great-britain_osm・asia_osmの3件をグラフ単位で大規模実験へ移管した。CPU・Atomicのp200前処理下限が物理RAM24 GiBを超えるため。通常比較は56グラフ（共通38＋Sparse専用18）、282設定×5seed×3回＝4,230実行。タイルと合わせ今回6,030実行。移管した135実行は失敗・成功に数えず今回の予定から除外し、後日のRR GPU専用実験へ75実行を追加する。NACA0015とFlan_1565は、その後のユーザー指定でautoとともに大規模側へ移管した。
