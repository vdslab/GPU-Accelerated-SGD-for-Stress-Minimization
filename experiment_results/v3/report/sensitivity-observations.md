# v3 No6・No7：core一巡の感度実験メモ

対象は正式core 3,210条件が終了した時点の `raw/results.jsonl`。No6は330条件、No7は360条件で、後続のSNAP原配布補完90条件はこのメモに含めない。集計scriptの実行・作図は行わず、標準Pythonでmetadataだけを照合した。全138のグラフ・手法・パラメータ条件について、中央値・幅・対応n・状態・再利用元を[条件別CSV](sensitivity-core-metadata.csv)へ保存した。

## 集計の定義

- seed 0〜4の成功recordを対象とする。CPU比は同グラフ・同seed（No7では同P）の入力・初期座標・前処理hash、反復数・epsilon、stress評価定義の一致を確認し、各seedの比を求めてからグラフ内で中央値にする。種ごとの平均や、中央値同士の比は使わない。GPU/CPU stress比は小さいほどよく、CPU/GPU時間比は大きいほど速い。
- 5seed完備条件だけを最短・No6の非劣位条件へ採用する。絶対stress・時間・RSSは成功seedの中央値であり、部分成功はnを併記する。No6のCPU参考はbasic Full CPUの5seedが完備した場合だけ採用し、今回の6グラフはいずれも5/5。CPUはT比較の測定点ではない。
- SGD秒は反復区間の合計でtrace出力・座標copyを除く。cold秒は前処理・手法setup・GPU初期化・upload・SGD・readbackを含み、入力読込・最終stress評価・出力を除く。process wallはnative全体を含み、終了後archiveは両者の外。CPUの反復前clone等、SGD外の費用にも注意する。
- Full stressはNo6のfe_4elt2とNo7の全グラフで固定256起点・評価seed 0の推定値、それ以外のNo6はexact。推定値とexactを横断して大小比較しない。RSSはprocessの観測最大値でGPU専用VRAMではない。

この2条件は全5完備の最短比較から除外する。特にcoAuthorsCiteseerは生存した1seedだけの値で、成功分RSS 8.070 GiBは8 GiB設定を上回る。約200 ms間隔の停止監視と終了時の観測最大RSSは厳密な瞬間上限ではなく、statusを書き換えたり「8 GiBに収まる」と解釈したりしない。

delaunay_n20はP=50のみ全手法5/5成功。P=100のCPU warmupは成功（wall 66.176秒・観測RSS 7.959 GiB）したが、正式5実行はすべてmemory_limit。P=100 Atomic/RRは各1回、P=400全3手法は各1回のwarmupがmemory_limitとなり、新規の正式25枠が未起動になった。P=200全3手法も各1回のbasic warmupのmemory_limitから正式15枠が未起動で、その結果をNo7へ再利用した。従ってNo7に関係するwarmup失敗は重複を除くと8実行（P=100の2、P=200の3、P=400の3）で、うち新規P比較の失敗は5実行。warmup成功1回が全seedのメモリ適合を保証しない例でもある。

Pを変えるとpivot・制約数・重み・学習率の系列だけでなく、共有RNGの消費に伴って初期配置も変わる。同じP内のCPU/GPU対応では初期座標・前処理hash一致を確認したが、P間は同一初期配置の対照実験ではない。従って上記はPを含む設定全体の感度であり、Pだけの因果効果とは解釈しない。
