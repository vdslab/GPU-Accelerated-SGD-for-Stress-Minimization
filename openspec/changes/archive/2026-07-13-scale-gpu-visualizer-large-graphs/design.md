## Context

現行の `gpu_visualizer` は、結果TXTを読み込んだ後、CPUで各頂点を始点とするBFSを実行して全非連結頂点対のストレスを厳密計算し、その後でWGPUによるPNG描画を行う。`MAX_N_FOR_STRESS` が実質無制限なので、計算量は非重み付きグラフでも概ね `O(|V|(|V|+|E|))` となり、30,000頂点以上で描画器の性能を評価する前に長時間停止する。

GPU側では、辺ごとに両端の `[f32; 2]` 座標を展開しており、同じ頂点座標を次数分だけ複製している。25万頂点・約194万辺では展開済み辺座標だけで約31 MBを要し、CPUの一時ベクタとGPUバッファの双方に同じ構造を持つ。共有頂点座標と `u32` インデックスなら、頂点約2 MBと辺インデックス約16 MBで表現できる。

参照論文の25万頂点例は、低ランク抵抗距離と標本化によってレイアウト計算を大規模化した結果である。今回の対象は既に生成された座標の可視化なので、抵抗距離レイアウトを再実装するのではなく、描画前評価を有界化し、GPU投入形式を改善する。

## Goals / Non-Goals

**Goals:**

- 通常の `cargo run` で、小規模グラフの厳密ストレス計算を維持しながら、大規模グラフでは有界時間の標本化推定へ自動的に切り替える。
- 25万頂点・約200万辺の座標を、厳密全点対計算、辺座標の重複保持、GPU validation errorなしで2048×2048 PNGへ描画する。
- 厳密値・近似値・省略を出力上で明確に区別し、再現条件と各段階の時間を確認可能にする。
- 既存TXT形式および小規模入力の描画結果・厳密ストレス値との互換性を保つ。

**Non-Goals:**

- Sparse SGD、RR-SGD、Omega、抵抗距離などのレイアウトアルゴリズムを変更または実装すること。
- 近似ストレスを論文掲載の厳密ストレスと同一視すること。
- インタラクティブなズーム、パン、タイル配信を備えたGUIを作ること。
- すべてのGPUで一定の秒数を保証すること。

## Decisions

### 1. ストレス評価を4モードに分離する

CLIに `--stress auto|exact|sampled|off`、`--stress-samples <K>`、`--stress-seed <SEED>` を追加する。既定の `auto` は `|V| <= 8,000` で従来の厳密計算を行い、それを超える場合は既定64始点の標本化計算へ切り替える。`exact` は規模にかかわらず厳密計算するが、大規模入力では実行前に計算量警告を表示する。`off` は描画だけを行う。

標本化ではseedから再現可能に、重複なしで始点集合 `S` を選ぶ。各始点について全到達先への従来と同じストレス項の和 `C_i` をBFSで求め、無向頂点対全体の推定値を `|V| / (2|S|) * Σ(i∈S) C_i` とする。始点を一様標本化する限り不偏で、計算量は `O(K(|V|+|E|))`、追加作業メモリは `O(|V|)` である。非連結頂点対は従来どおり評価対象外とする。

代替案として大規模入力では常にストレスを省略する方法があるが、レイアウト品質の概算比較ができない。全頂点対のGPU計算は大幅な実装追加と巨大な計算量が残るため採用しない。

### 2. 辺を共有座標とインデックスで描画する

正規化済みノード座標を1つのvertex bufferへ格納し、各辺を2個の `u32` indexとしてindex bufferへ格納する。WGPUのline-list pipelineから `draw_indexed` を呼び、ノード描画も同じ座標データをinstance入力として再利用する。入力時に頂点数が `u32` で表現可能か、全辺端点が範囲内か、要求バッファサイズがadapter/device limit以内かを検証し、GPUエラーより前に具体的な診断を返す。

代替のstorage buffer参照やcompute shaderによる線分展開は柔軟だが、単純な無向辺の描画には複雑さが増える。WGPUの標準indexed drawingを優先する。

### 3. 既定では全辺を保ち、ノードだけ自動LODを適用する

出力解像度と頂点数から1頂点当たりの画素密度を求め、ノード半径を大規模時に1px程度まで縮小する。`--node-radius <PX>` で自動値を上書きできる。辺は比較可能性を保つため既定ですべて描画する。極端な密度や低性能GPU向けには `--max-edges <N>` を明示した場合だけ、seedに基づく決定的な標本化を行い、描画辺数と総辺数を表示する。

ノードを常に4pxで描く案は25万頂点では画面を覆うため採用しない。既定の辺間引きは構造を隠してしまうため採用しない。

### 4. 読込と計測を大規模入力向けに整える

結果TXTのnode/edge countメタデータを読み、可能な場合は各ベクタを事前確保する。座標数、有限値、辺端点をCPU上で検証する。ターミナルには、入力規模、ストレスモードと条件、読込、ストレス、GPU準備・転送/描画/読戻し、PNG encode、合計を分けて表示する。近似値は `Approx stress` と表示し、厳密な `Stress` と同じラベルを使わない。

### 5. 大規模fixtureは生成式で検証する

巨大なTXTやPNGをリポジトリへ追加せず、テストまたは補助スクリプトで25万頂点・約200万辺の連結グラフと有限座標を決定的に生成する。CIで常時GPU性能を要求せず、CPU単体テストではストレス推定・入力検証・バッファ構築量を確認し、Apple M4 Pro等の実GPUでは手動の受入コマンドで2048×2048 PNG生成と段階別時間を記録する。

## Risks / Trade-offs

- [64始点の近似ストレスはグラフによって分散が大きい] → seedと標本数を常に表示し、`--stress-samples` で精度と時間を調整可能にする。小規模fixtureで複数seedの誤差も検証する。
- [indexed line-listの対応上限はGPUに依存する] → adapter limitを取得して必要サイズと比較し、要求を満たさない場合は必要量を含むエラーを返す。利用者は明示的な辺上限へ切り替えられる。
- [全辺描画はGPUメモリに収まってもoverdrawで遅くなる] → ノードLOD、任意の辺上限、段階別計測を提供し、隠れた自動間引きは行わない。
- [autoの閾値変更で従来と表示値が変わる] → 8,000以下は従来の厳密計算を維持し、それ以上は近似であることをラベルと条件で明示する。`exact` で従来動作へ戻せる。
- [PNG encodeと読戻しがGPU描画後の支配時間になる] → 各時間を分離表示し、ボトルネックを誤認しないようにする。画像形式追加は今回の範囲外とする。

## Migration Plan

1. ストレスAPIを結果種別付きにし、従来の厳密計算を回帰テストで固定する。
2. CLIとauto/sample/offの分岐を導入し、大規模入力が厳密経路へ入らないことを確認する。
3. 辺レンダリングをindexed drawingへ置換し、小規模fixtureの画像と辺数を比較する。
4. LOD、入力検証、段階別計測を追加する。
5. 25万頂点・約200万辺fixtureで実GPU受入試験を行い、問題時は旧実装へ戻すのではなく `--max-edges` を診断用フォールバックとして使用する。

## Open Questions

- 64始点でUSpowerGridや既存ベンチマーク群の比較に十分な分散になるかは実装時に測定し、必要なら既定値だけを根拠付きで調整する。
- WGPUのtimestamp queryは環境差があるため、初期実装はCPU側wall-clockでGPU submit完了までを計測し、query対応は将来拡張とする。
