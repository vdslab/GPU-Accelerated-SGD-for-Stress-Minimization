## 背景と目的

既存の CPU ベースラインは、到達可能な全頂点対について最短路制約を生成するため、大規模グラフでは SGD の1回の反復に必要なメモリと計算量が頂点数の二乗になります。GPU 高速化の導入や比較に先立ち、pivot に基づく Sparse SGD アルゴリズムを評価できる、疎な CPU ベースラインが必要です。

## 変更内容

- `baseline-sgd-non-gpu` の入力・出力・実行フローを参考に、`baseline-sparse-sgd-non-gpu` という独立した Rust crate を追加します。
- ランダム化 max-min サンプリングによって設定可能な数の pivot を選択し、選択した pivot からのみ最短路距離を計算します。
- 全頂点と pivot の組から Sparse SGD の制約を構築し、グラフの辺に対する距離1の制約も保持します。
- ランダム化された制約順序と既存実装と同様のアニーリングスケジュールを使用して、CPU 上で Sparse SGD の更新を実行します。
- ランダムに初期化したレイアウトと処理後のレイアウトを、既存の CPU ベースラインと同じテキスト形式で保存します。
- pivot 選択、疎制約、学習率、座標更新に対する単体テストを追加します。

## 機能

### 新規機能

- `cpu-sparse-sgd`: グラフの前処理、レイアウト最適化、結果出力を含む、CPU のみで動作する pivot ベースの Sparse SGD ストレス最小化機能。

### 変更する既存機能

なし。

## 影響範囲

- 新しい `baseline-sparse-sgd-non-gpu/` crate と、その Rust ソースコードおよびテストコードを追加します。
- `baseline-sgd-non-gpu` 自体は変更せず、リポジトリ既存の Matrix Market グラフ入力と出力ディレクトリの規約を再利用します。
- グラフ探索と乱数処理は CPU 上で実行し、GPU API や GPU ハードウェアを必要としません。
- 可能な範囲で既存ベースラインと依存関係を揃えますが、新しい crate には未使用の GPU 関連依存を含めません。
