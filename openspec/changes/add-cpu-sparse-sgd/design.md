## 背景

`baseline-sgd-non-gpu` は、Matrix Market 形式のグラフを読み込み、重みなし全点対最短路を計算し、到達可能な全頂点対をストレス制約へ変換して、ランダム化 SGD を実行する Rust 製の CPU 参照実装です。最後に初期レイアウトと最終レイアウトをファイルへ書き出します。この実装の全点対距離行列と制約リストは、頂点数に対して二乗の大きさになります。

要求された Sparse SGD は、提示されたアルゴリズムに従います。`h` 個の pivot を選択し、頂点と pivot の間の最短路制約および元グラフの辺制約だけを保持して、二次元のランダムレイアウトにアニーリングスケジュール付きの対称 SGD 更新を適用します。新しいベースラインは既存実行ファイルと容易に比較でき、GPU API に依存しない必要があります。

## 目標と対象外

**目標:**

- 単独で実行できる `baseline-sparse-sgd-non-gpu` Rust crate を追加します。
- 保存する距離と制約を全頂点対から、pivot を始点とする距離および疎制約へ削減します。
- 該当する範囲で、既存 CPU ベースラインのグラフ入力、アニーリング、座標更新、時間計測、出力規約を維持します。
- pivot 選択、制約構築、最適化処理を個別にテスト可能にします。
- 重複辺、非連結グラフ、座標が一致する頂点、頂点数を超える pivot 数を安全に扱います。

**対象外:**

- GPU 高速化および既存 GPU 実装の変更。
- `baseline-sgd-non-gpu` の置き換えや変更。
- Matrix Market の辺の重みや重み付き最短路への対応。
- 実行ごとに同一レイアウトを保証すること。pivot 選択、初期配置、制約順序は意図的にランダムとします。
- 既存ベースラインの設定方法を超える汎用的なコマンドラインインターフェースの実装。

## 設計上の判断

### 独立した CPU 専用 crate とする

新しいディレクトリは、既存ベースラインと同様に `main.rs`、`graph.rs`、`algorithm.rs` へ責務を分割します。一方、マニフェストには、グラフ読み込み、乱数処理、エラー処理、日時、ログに実際に必要な CPU 向け依存だけを含め、不要な `wgpu` 依存は追加しません。

代替案として、`baseline-sgd-non-gpu` に疎モードを追加する方法があります。しかし、ユーザーが新しいベースライン用ディレクトリを求めており、ベンチマーク名と出力名を明確に分離できるため、独立した crate を採用します。

### 反復 BFS とランダム化 max-min サンプリングを使用する

最初の pivot は全頂点から一様ランダムに選びます。pivot を追加するたびに、その pivot を始点とする BFS を実行し、各頂点から pivot 集合までの既知の最小距離を更新します。次の pivot は、未選択頂点のうち最小距離が最大となる頂点からランダムに選択します。到達不能を表す値は有限距離より大きいものとして扱い、既に網羅された連結成分内で pivot を重複して増やす前に、非連結成分を網羅します。要求された pivot 数は頂点数以下に制限します。

この方法の探索時間は `O(h(n+m))`、グラフと距離の保持量は `O(n+m+nh)` です。`O(n²)` の距離行列は構築しません。同率候補からランダムに選ぶことで、`MaxMinRandomSP` の意図を維持します。

代替案として、最初に全点対距離を計算してから pivot を選択する方法があります。選択処理は単純になりますが、疎実装の主な目的であるメモリ削減を達成できないため採用しません。

### 制約を正規化して重複排除する

各頂点対は、端点を `(min(i,j), max(i,j))` の順に並べて保存します。この頂点対をキーとするマップへ、到達可能かつ自己対でない頂点と pivot の関係を追加します。その後、元グラフの辺を距離1、重み1の制約として追加し、同じキーがあれば上書きします。最後にマップをベクターへ変換し、SGD の各反復でランダムに並べ替えます。

これにより集合和 `E ∪ (V × P)` を実現し、pivot 同士の重複、Matrix Market 入力中の重複辺、辺と pivot 制約の重複による偏りを防ぎます。到達不能な pivot 関係には有限のストレス目標値がないため、制約へ追加しません。

代替案として、生成した関係をすべてベクターへ追加する方法があります。実装は単純ですが、pivot の順序や入力中の重複によって実効的な重みが変化するため採用しません。

### 既存ベースラインの座標更新とアニーリングを再利用する

最適化処理は、学習率ごとに制約をシャッフルします。差分ベクトル `x_j - x_i` のノルムを `r` とし、既存ベースラインと同じ半変位 `(r - d_ij) / (2r)` を計算します。`mu` を `min(w_ij * eta, 1)` に制限し、両端の座標へ大きさが等しく向きが反対の更新を適用します。両端の座標が一致する場合は、除算前に微小なランダム方向を与えます。指数減衰スケジュールは、既存ベースラインと同様に有限な制約重みの最小値と最大値から計算します。

この動作を維持することで、比較実験における主な変数を疎化に限定します。テストでは、小さな純粋関数または乱数生成器の注入を使用して、実運用時のランダム性を保ったまま決定的に不変条件を検証します。

### 出力形式を既存ベースラインと互換にする

`main.rs` は、既存と同じデータセット名とタイムスタンプによる命名規則を使用し、グラフのメタデータ、辺、座標を同じ順序とテキスト構造で書き出します。実装名とファイル名の接頭辞だけを `baseline-sparse-sgd-non-gpu` に変更します。pivot 数は、既存の反復回数、epsilon、中心化と同じ場所で明示的な実行パラメータとして設定します。

## リスクとトレードオフ

- [疎制約は完全なストレスを近似するため、`h` が小さいとレイアウト品質が低下する可能性がある] → `h` を明示的な値とし、設定を比較できるようコードと出力メタデータへ記録します。
- [pivot 選択と SGD の制約順序がランダムなため、結果を完全には再現できない] → 実運用時のランダム性は維持し、テストでは乱数生成器の注入または固定 seed により決定的な不変条件を検証します。
- [非連結グラフでは連結成分間に有限のグラフ距離が存在しない] → 未網羅の連結成分を優先して pivot を選び、無効な重みを生成せず到達不能な関係を除外します。
- [ハッシュマップの反復順序は不定である] → 各アニーリング反復で必ずシャッフルするため制約の初期順序に意味を持たせず、テストではベクター順序ではなく集合として比較します。
- [`h` を非常に大きくすると全点対計算に近づく] → `h` を制限し、前処理が `O(h(n+m))`、制約数が `O(nh+m)` であることを記録します。

## 導入手順

1. 既存ベースラインを変更せず、新しい crate を追加します。
2. 新しい crate 単体で Cargo によるビルドとテストを実行します。
3. リポジトリ内の小規模データセットでスモークテストを行い、初期・処理後の両出力に有限の座標だけが含まれることを確認します。
4. 新しいベースラインを取り消す必要がある場合は、そのディレクトリを削除します。既存 API や保存データの移行は不要です。

## 未解決事項

なし。初回実装は既存ベースラインと同じくコード内で実行設定を指定します。コマンドラインからの設定変更は、必要に応じて別の変更として提案します。
